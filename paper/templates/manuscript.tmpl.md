## Abstract

### Background
Clinical and translational genomics increasingly rely on deep whole-genome sequencing (WGS), tumor-normal somatic profiling, and ultra-deep circulating tumor DNA (ctDNA) minimal residual disease (MRD) panels to detect single-nucleotide variants (SNVs), complex multinucleotide variants (MNVs), insertions/deletions (indels), splice-site alterations, and structural variants (SVs) across allele frequencies spanning germline heterozygosity down to sub-percent somatic mosaicism. For a decade, the VarDict algorithm (`VarDictJava` v1.8.3) has served as a cornerstone heuristic-aware local realigner and variant caller across oncology and rare-disease pipelines. However, its fragmented three-language execution architecture—streaming binary alignment maps (BAMs) through a Java Virtual Machine (JVM) pileup engine into external R (`teststrandbias.R` / `testsomatic.R`) and Perl (`var2vcf_valid.pl` / `var2vcf_paired.pl`) post-processors—imposes severe memory retention, inter-process serialization bottlenecks, and unhandled runtime crashes on modern high-depth datasets. Existing C++ reimplementations (`vardictcpp`) improve speed on pre-chunked exome targets but omit critical modes (splicing, amplicon, structural variants, CRAM), introduce silent algorithmic divergences, and retain unbounded per-interval memory growth on full chromosomes.

### Conclusions
`VarDictRust` demonstrates that a complex, heuristic-rich legacy bioinformatics pipeline can be consolidated into a statically linked (`{{m:s5_h4_musl_mb}}` MB `x86_64-unknown-linux-musl`), memory-bounded systems binary without sacrificing byte-level statistical and allele fidelity. By enforcing bounded tile-plus-halo streaming (`O(tile + halo)` memory) and eliminating `{{m:s5_h4_conda_pkgs}}` runtime JVM/R/Perl environment packages, `VarDictRust` enables deterministic, crash-free variant discovery from targeted clinical panels and RNA-seq splice analysis to un-chunked deep whole genomes and `{{m:s6_tit_vaf_1_pct}}`-VAF liquid-biopsy titrations.

## Background

Accurate detection of somatic and germline sequence variants across heterogeneous sequencing chemistries and clinical assay modalities remains a central challenge in computational genomics [1, 2]. Whereas germline variant callers such as `FreeBayes` [3], `Strelka2` [4], `Octopus` [5], and `DeepVariant` [6] model diploid genotype likelihoods, clinical oncology assays must resolve somatic single-nucleotide variants (SNVs), complex multinucleotide variants (MNVs), insertions/deletions (indels), and structural variants (SVs) across variable tumor purities, subclonal architectures, and circulating cell-free DNA (cfDNA) fractions down to `{{m:s6_tit_vaf_1_pct}}`–`{{m:s6_tit_vaf_2_pct}}` variant allele frequency (VAF) [7, 8]. Originally introduced by Lai et al. in 2016 [1], `VarDict` (`VarDictJava` v1.8.3) uniquely combines local Smith-Waterman-like soft-clip and indel realignment (`CigarModifier` and `VariationRealigner`), composite complex-variant phasing, amplicon primer-edge filtering (`-a`), RNA-seq exon-junction splice-site accounting (`-i`), and inline structural variant breakpoint assembly within a unified statistical framework. Consequently, `VarDict` is widely deployed in clinical panel pipelines, `bcbio-nextgen`, `nf-core/sarek`, and multi-caller somatic consensus ensembles [9, 10].

Despite its algorithmic versatility, the reference `VarDictJava` v1.8.3 implementation suffers from four structural limitations that impede its deployment on modern deep whole-genome sequencing (WGS) and cloud-native clinical infrastructure:

1. **Fragmented Three-Language Pipeline and IPC Overhead.** `VarDictJava` does not directly emit Variant Call Format (VCF) records. Instead, the Java process emits an intermediate `36`- to `61`-column tab-delimited `.var` stream (`Simple` `36/38`, `Amplicon` `38/40`, `Somatic` `55/61` columns without/with `--fisher`), which is piped via standard output to an external R script (`teststrandbias.R` for single-sample strand-bias Fisher exact testing or `testsomatic.R` for paired tumor-normal allele and strand-bias Fisher exact tests), and subsequently piped into a Perl post-processor (`var2vcf_valid.pl` or `var2vcf_paired.pl`) to apply quality/frequency filters and format VCF 4.3 records (`Figure 1`). When the `--fisher` flag is invoked inside Java to bypass R, the Perl stage remains mandatory, requiring a runtime software stack comprising `{{m:s5_h4_conda_pkgs}}` Conda packages across OpenJDK, R (`statmod`), and Perl (`Getopt::Long`, `warnings`).
2. **Unbounded JVM Heap Retention on Contiguous Genomic Spans.** `VarDictJava` allocates dense per-position pileup maps (`Map<Integer, VariationMap<String, Variation>>` and reference base arrays) spanning the entire requested BED interval or `-R` region prior to variant finalization (`ToVarsBuilder`) and local realignment (`VariationRealigner`). While manageable on exome capture baits (`<10` kbp), invoking `VarDictJava` on contiguous megabase or chromosome-scale intervals causes Resident Set Size (RSS) to scale linearly with interval length (`O(L × depth)`), triggering fatal `java.lang.OutOfMemoryError: Java heap space` (`rc=3`) crashes or extreme garbage-collection stalls exceeding `100`–`200` GiB RAM on whole chromosomes (`Table 2`, `Table 5`).
3. **Silent Truncation and Crashes on Edge-Case Alignments.** Over `30` upstream GitHub issues in `VarDictJava` (`#7`, `#38`, `#187`, `#197`, `#243`, `#249`, `#253`, `#282`, `#283`, `#320`, `#341`, `#380`, `#384`) document `NullPointerException`, `StringIndexOutOfBoundsException`, `ArrayIndexOutOfBoundsException` in `CigarModifier.modifyCigar` on supplementary or heavily soft-clipped reads, non-deterministic output row ordering due to unseeded `java.util.HashMap` iteration (`#282`), broken CRAM reference decoding (`#249`, `#380`), and truncated `##contig` VCF header metadata (`#320`).
4. **Incomplete C++ Port (`vardictcpp`).** Recently, Wolff et al. (2026) introduced `vardictcpp` (`{{m:cpp_version}}`), a C++/htslib reimplementation targeting single-sample and paired somatic speedups [11]. However, our systematic 3-way audit reveals ten structural and algorithmic divergences (`CPP-1` through `CPP-10`, cataloged in `Table 8` and `Supplementary Table S6`): `vardictcpp` lacks a native VCF emitter, omits amplicon (`-a`), RNA splice (`-i`), and structural variant modes (`--nosv` is forced by default and SV calling is unsupported), fails to decode CRAM alignments (`-G`), crashes (`SIGABRT` / `std::out_of_range`) on `-R` region strings lacking a colon, drops single-end reads during realignment, diverges in Fisher exact odds-ratio and p-value rounding, and—critically—allocates unbounded memory across large intervals (`{{m:s5_hg002_contigs_cpp_rss_gb}}` GB on HG002 WGS and `{{m:s5_hg008_contigs_cpp_rss_gb}}` GB with a `3`-hour timeout `rc=124` on HG008 WGS) unless the user manually pre-splits BED files via an external wrapper (`CPP_CHUNK={{m:cpp_chunk_bp}}`).

To resolve these challenges without altering the clinically validated statistical behavior of `VarDict`, we engineered `VarDictRust` (`v{{m:version}}`) under the [rewrites.bio](https://rewrites.bio) prime directive: produce a memory-safe, single-binary Rust implementation whose output is byte- and float-equivalent (`ε = {{m:eps_tol}}`) to `VarDictJava` v1.8.3 on all valid inputs, while eliminating runtime panics and bounding peak memory to `O(tile + halo)` regardless of chromosome length or sequencing depth.

### Bounded Memory Scaling, Multicore Work-Stealing, and Multi-Tenant Node Packing

A central architectural claim of `VarDictRust` is that peak memory consumption is bounded by `O(threads × (tile + halo))` rather than scaling with chromosome span or BED interval count (`Figure 4`, `Table 4`). We tested this property across four complementary Stage 4 experiments (`s4_perf_budget_4targets_n3`, `s4_scale_exome_3way_th1`..`s4_scale_exome_3way_th32`, `s4_span_chr1_3way_th8`..`s4_span_chr1_3way_th32`, `s4_span_chr1_f0`, and `s4_jobs_per_node_2x4c_n3`):

1. **Four-Target Performance Budget Gate (`s4_perf_budget_4targets_n3` and `sweep_4targets_full`):** Across `n = 3` technical replicates on `amplicon-tier2` (`{{m:s4_pb_amplicon_tier2_rust_wall_s}}` s vs `{{m:s4_pb_amplicon_tier2_java_wall_s}}` s Java, wall ratio `{{m:s4_pb_amplicon_tier2_wall_ratio}}`, RSS ratio `{{m:s4_pb_amplicon_tier2_rss_ratio}}`), `hg002-tier2` (`{{m:s4_pb_hg002_tier2_rust_wall_s}}` s vs `{{m:s4_pb_hg002_tier2_java_wall_s}}` s Java, `{{m:s4_pb_hg002_tier2_rust_rss_mb}}` MB vs `{{m:s4_pb_hg002_tier2_java_rss_mb}}` MB, wall ratio `{{m:s4_pb_hg002_tier2_wall_ratio}}`, RSS ratio `{{m:s4_pb_hg002_tier2_rss_ratio}}`), `hg008-tier2` (`{{m:s4_pb_hg008_tier2_rust_wall_s}}` s vs `{{m:s4_pb_hg008_tier2_java_wall_s}}` s Java, `{{m:s4_pb_hg008_tier2_rust_rss_mb}}` MB vs `{{m:s4_pb_hg008_tier2_java_rss_mb}}` MB, wall ratio `{{m:s4_pb_hg008_tier2_wall_ratio}}`, RSS ratio `{{m:s4_pb_hg008_tier2_rss_ratio}}`), and `seqc2-exome-tier2` (`{{m:s4_pb_seqc2_exome_tier2_rust_wall_s}}` s vs `{{m:s4_pb_seqc2_exome_tier2_java_wall_s}}` s Java, `{{m:s4_pb_seqc2_exome_tier2_rust_rss_mb}}` MB vs `{{m:s4_pb_seqc2_exome_tier2_java_rss_mb}}` MB, wall ratio `{{m:s4_pb_seqc2_exome_tier2_wall_ratio}}`, RSS ratio `{{m:s4_pb_seqc2_exome_tier2_rss_ratio}}`), `VarDictRust` satisfied all CI performance budgets by wide margins.
2. **Whole-Exome Multicore Scaling (`1` to `32` Threads, `s4_scale_exome_3way_th1`..`th32`):** On the SEQC2 HCC1395 whole exome (`{{m:s4_exome_total_vars}}` total variants, `{{m:s4_exome_vars}}` `PASS` variants, `n = 3` replicates per thread count; `Table 4`, `Figure 4a`), `VarDictRust` scaled smoothly from `{{m:s4_exome_th1_rust_wall_s}}` s (`{{m:s4_exome_th1_rust_rss_mb}}` MB / `{{m:s4_exome_th1_rust_rss_gib}}` GiB RSS) at `1` thread to `{{m:s4_exome_th2_rust_wall_s}}` s (`{{m:s4_exome_th2_rust_sp}}`× self-speedup) at `2` threads, `{{m:s4_exome_th4_rust_wall_s}}` s (`{{m:s4_exome_th4_rust_sp}}`×) at `4` threads, `{{m:s4_exome_th8_rust_wall_s}}` s (`{{m:s4_exome_th8_rust_sp}}`×) at `8` threads, `{{m:s4_exome_th16_rust_wall_s}}` s (`{{m:s4_exome_th16_rust_sp}}`×) at `16` threads, and `{{m:s4_exome_th32_rust_wall_s}}` s (`{{m:s4_exome_th32_rust_sp}}`× self-speedup, `{{m:s4_exome_th32_rust_rss_mb}}` MB / `{{m:s4_exome_th32_rust_rss_gib}}` GiB RSS) at `32` threads. By contrast, `VarDictJava`'s runtime plateaued above `8` threads (`{{m:s4_exome_th1_java_wall_s}}` s at `1` thread, `{{m:s4_exome_th8_java_wall_s}}` s at `8` threads, `{{m:s4_exome_th32_java_wall_s}}` s at `32` threads) due to single-threaded Perl/R post-processing and JVM GC contention, while its heap bloated from `{{m:s4_exome_th1_java_rss_gib}}` GiB (`1` thread) to `{{m:s4_exome_th32_java_rss_gib}}` GiB (`32` threads)—making `VarDictRust` `{{m:s4_exome_th32_speedup_vs_java}}`× faster and `{{m:s4_exome_th32_rss_ratio_vs_java}}`× lower in peak RSS at `32` threads (`{{m:s4_exome_th32_rss_ratio_vs_cpp}}`× lower RSS than `vardictcpp` at `{{m:s4_exome_th32_cpp_rss_gib}}` GiB).

### Full-Genome WGS Scaling: Un-Chunked Chromosomes (Arm A) Versus Pre-Chunked GIAB Intervals (Arm B)

To evaluate whole-genome scalability under realistic production conditions, Stage 5 compared all three engines at `32` threads across two massive full-genome GRCh38 datasets: the `{{m:s5_hg002_bam_gb}}` GB NIST HG002 `2×250` bp Illumina germline WGS BAM and the `{{m:s5_hg008_bam_gb}}` GB NIST HG008 `364`× combined (`195`× tumor / `169`× normal) paired somatic WGS BAMs (`Table 5`, `Figure 5`). For each genome, we tested two region-definition protocols:
- **Arm A (Un-chunked Full Contigs, `22` autosomes, `{{m:s5_contigs_bp}}` bp):** `s5_wgs_hg002_full_contigs_3way_th32` and `s5_wgs_hg008_full_contigs_3way_th32`. Each chromosome (`chr1`–`chr22`) is passed as a single full-length BED line, testing whether the engine can natively stream whole chromosomes without external script intervention.
- **Arm B (`≤{{m:giab_arm_b_max_kbp}}` kbp Pre-Chunked GIAB Callable Regions):** `s5_wgs_hg002_full_giab_3way_th32` (`{{m:s5_hg002_giab_intervals}}` intervals, `{{m:s5_hg002_giab_gbp}}` Gbp) and `s5_wgs_hg008_full_giab_3way_th32` (`{{m:s5_hg008_giab_intervals}}` intervals, `{{m:s5_hg008_giab_gbp}}` Gbp), where intervals are artificially pre-split at `≤{{m:giab_arm_b_max_kbp}}` kbp (`CPP_CHUNK={{m:cpp_chunk_bp}}`) to accommodate `VarDictJava` and `vardictcpp`.

The contrast between Arm A and Arm B exposes the fundamental limitation of whole-interval allocation (`Table 5`, `Figure 5`):
- **Arm A (Un-chunked Chromosomes):** On HG002 full contigs (`s5_wgs_hg002_full_contigs_3way_th32`), `VarDictJava` (`-Xmx200g`) exhausted `{{m:s5_hg002_contigs_java_rss_gb}}` GB RAM and crashed (`rc=3` `OutOfMemoryError`). `vardictcpp` completed in `{{m:s5_hg002_contigs_cpp_wall_str}}` (`mm:ss`) but required `{{m:s5_hg002_contigs_cpp_rss_gb}}` GB peak RSS (`{{m:s5_hg002_contigs_cpp_rss_ratio_vs_rust}}`× higher than `VarDictRust`) and emitted `{{m:s5_hg002_contigs_cpp_vars}}` variants (`{{m:s5_hg002_contigs_cpp_excess}}` excess un-deduplicated chunk-boundary/filter artifacts relative to `VarDictRust`'s `{{m:s5_hg002_contigs_rust_vars}}` variants). `VarDictRust` completed all `22` chromosomes in `{{m:s5_hg002_contigs_rust_wall_str}}` (`{{m:s5_hg002_contigs_rust_wall_s}}` s) at just `{{m:s5_hg002_contigs_rust_rss_gb}}` GB (`{{m:s5_hg002_contigs_rust_rss_gib}}` GiB) peak RSS. On the `{{m:s5_hg008_bam_gb}}` GB `364`× HG008 paired somatic WGS (`s5_wgs_hg008_full_contigs_3way_th32`), `VarDictJava` crashed with OOM at `{{m:s5_hg008_contigs_java_rss_gb}}` GB (`rc=3`), and `vardictcpp` ballooned to `{{m:s5_hg008_contigs_cpp_rss_gb}}` GB RSS (`{{m:s5_hg008_contigs_cpp_rss_ratio_vs_rust}}`× higher than `VarDictRust`, `{{m:s5_hg008_contigs_cpp_vars}}` raw rows) before hitting the `3`-hour wall-clock timeout (`rc=124`). `VarDictRust` was the *only* engine to complete un-chunked `364`× somatic WGS, finishing in `{{m:s5_hg008_contigs_rust_wall_str}}` (`h:mm:ss`) at `{{m:s5_hg008_contigs_rust_rss_gb}}` GB (`{{m:s5_hg008_contigs_rust_rss_gib}}` GiB) peak RSS and emitting `{{m:s5_hg008_contigs_rust_vars}}` somatic/germline variants.
- **Arm B (`≤{{m:giab_arm_b_max_kbp}}` kbp Pre-Chunked GIAB Callable Regions):** When intervals were pre-split to `≤{{m:giab_arm_b_max_kbp}}` kbp (`s5_wgs_hg002_full_giab_3way_th32`), `VarDictJava` finally completed HG002 WGS in `{{m:s5_hg002_giab_java_wall_str}}` (`h:mm:ss`) at `{{m:s5_hg002_giab_java_rss_gb}}` GB RSS. `VarDictRust` finished in `{{m:s5_hg002_giab_rust_wall_str}}` (`{{m:s5_hg002_giab_rust_wall_s}}` s) at `{{m:s5_hg002_giab_rust_rss_gb}}` GB (`{{m:s5_hg002_giab_rust_rss_gib}}` GiB) RSS—a `{{m:s5_hg002_giab_speedup_vs_java}}`× speedup and `{{m:s5_hg002_giab_rss_ratio_vs_java}}`× memory reduction over `VarDictJava` (and `{{m:s5_hg002_giab_rss_ratio_vs_cpp}}`× lower RSS than `vardictcpp`'s `{{m:s5_hg002_giab_cpp_rss_gb}}` GB in `{{m:s5_hg002_giab_cpp_wall_str}}`), while matching `VarDictJava` across `{{m:s5_hg002_giab_vars}}` variants (with `vardictcpp` differing by `{{m:s5_hg002_giab_cpp_diff_vars}}` variants at `{{m:s5_hg002_giab_cpp_vars}}`) and achieving `rtg vcfeval` full-genome $F_1 = {{m:s5_hg002_wgs_f1_best}}$ (precision `{{m:s5_hg002_wgs_p_best}}`, sensitivity `{{m:s5_hg002_wgs_r_best}}`; unfiltered $F_1 = {{m:s5_hg002_wgs_f1_none}}$, precision `{{m:s5_hg002_wgs_p_none}}`, sensitivity `{{m:s5_hg002_wgs_r_none}}`). On HG008 Arm B (`s5_wgs_hg008_full_giab_3way_th32`), both `VarDictJava` (`{{m:s5_hg008_giab_java_rss_gb}}` GB RSS) and `vardictcpp` (`{{m:s5_hg008_giab_cpp_rss_gb}}` GB RSS, `{{m:s5_hg008_giab_cpp_wall_str}}`, `{{m:s5_hg008_giab_cpp_vars}}` raw rows) timed out at `3` hours (`rc=124`), whereas `VarDictRust` completed in `{{m:s5_hg008_giab_rust_wall_str}}` at `{{m:s5_hg008_giab_rust_rss_gb}}` GB (`{{m:s5_hg008_giab_rust_rss_gib}}` GiB) RSS (`{{m:s5_hg008_giab_cpp_rss_ratio_vs_rust}}`× lower RSS than `vardictcpp`), emitting `{{m:s5_hg008_giab_rust_vars}}` variants and achieving full-genome somatic $F_1 = {{m:s5_hg008_wgs_v03_f1_best}}$ (`GIAB v0.3`) and $F_1 = {{m:s5_hg008_wgs_v04_f1_best}}$ (`GIAB v0.4`).

### Unlocking Next-Generation GIAB v5.0Q T2T-Q100, CMRG v1.00, and Mosaic v1.10 Discovery via Un-Chunked Calling

## Discussion

### Scientific Software Consolidation Under the `rewrites.bio` Specification
A recurring tension in bioinformatics software engineering is the trade-off between computational performance and clinical backward compatibility. When a widely deployed variant caller is rewritten for speed, subtle changes in Smith-Waterman tie-breaking, read-quality Phred offsetting, floating-point rounding, or strand-bias p-value calculation frequently alter downstream clinical callsets, forcing diagnostic laboratories through costly re-validation cycles. Conversely, line-by-line transliterations preserve bugs and memory anti-patterns. By adhering to the [rewrites.bio](https://rewrites.bio) methodology—separating **v1.0.x oracle parity and memory/crash robustness** from **post-1.0 opt-in algorithmic corrections (`--fix <id>`)**—`VarDictRust` resolves this tension. In default mode (`v{{m:version}}`), `VarDictRust` reproduces the exact allele calls, `FILTER` flags, somatic `STATUS` classifications, and `HALF_EVEN`-rounded Fisher exact statistics of `{{m:oracle_version}}` (`Table 1`, `Table S2`), while eliminating JVM `OutOfMemoryError` (`rc=3`) crashes, `CigarModifier` index-out-of-bounds panics (`#![forbid(unsafe_code)]`), and `java.util.HashMap` output-order non-determinism (`#282`). Known upstream output-affecting quirks in `VarDictJava` (such as `VD > DP` under complex realignment `#92`, aggressive `NM` filtering `#62`, `SHIFT3` coordinate shifts `#292`, and `<dup-N>` symbolic allele naming `#342`) are meticulously documented and deferred to post-1.0 opt-in `--fix` flags with strict diff-confinement gates.

### Why Bounded Tile-Plus-Halo Streaming Matters for Next-Generation T2T-Q100 and Clinical Genomics
Our Arm A versus Arm B whole-genome experiments (`Table 5`, `Table 7`, `Figure 5`, `Figure 7`) highlight an underappreciated consequence of memory-unbounded bioinformatics tools: **software memory limits silently dictate biological discovery masks**. Because `VarDictJava` allocates pileup state across an entire BED interval before variant emission, whole-genome users have historically been forced to restrict calling to pre-chunked `≤{{m:giab_arm_b_max_kbp}}` kbp BED masks (`GIAB v4.2.1`, `{{m:s5_hg002_giab_gbp}}` Gbp) or external `{{m:cpp_chunk_kbp}}` kbp bed-splitting wrappers (`CPP_CHUNK={{m:cpp_chunk_bp}}`). While `vardictcpp` accelerates pre-chunked exomes, it retains whole-interval memory allocation (`{{m:s2_rchr1_cpp_rss_gib}}` GiB on `chr1`, `{{m:s5_hg002_contigs_cpp_rss_gb}}` GB on HG002 Arm A, and `{{m:s5_hg008_contigs_cpp_rss_gb}}` GB with `rc=124` timeout on HG008 Arm A). By implementing internal `{{m:s1_tile_1m}}` bp tiling with a `{{m:rust_halo_kbp}}` kbp realignment halo and deterministic boundary deduplication (`s1_h1a_simple_tiles`), `VarDictRust` processes un-chunked full chromosomes in `{{m:s5_hg002_contigs_rust_rss_gb}}`–`{{m:s5_hg008_contigs_rust_rss_gb}}` GB RAM, unlocking `+{{m:s6_v50q_gain_gbp}}` Gbp of newly resolved `NIST GIAB v5.0Q T2T-Q100` sequence (`+{{m:s6_v50q_snv_r_gain_pct}}` SNV recall, `+{{m:s6_v50q_indel_r_gain_pct}}` indel recall) and `+{{m:s6_cmrg_snv_r_gain_pct}}` SNV / `+{{m:s6_cmrg_indel_r_gain_pct}}` indel recall across the `273` `NIST CMRG v1.00` genes (`Table 7`).

### Positioning Relative to Modern Deep-Learning and Commercial Somatic Callers
Our `{{m:s6_v04_total_callers}}`-caller evaluation on `NIST GIAB HG008 v0.4` (`Table 8`, `Figure 8`) clarifies the complementary strengths of heuristic pileup/realignment callers versus modern deep-learning (`DeepSomatic`, `ClairS`, `Ultima DeepVariant Somatic`), graph/local-assembly (`DRAGEN`, `Lancet2`, `Octopus`), and tumor-normal haplotype callers (`Hartwig SAGE`, `Mutect2`, `Strelka2`). At standard `364`× tumor-normal WGS depth, deep-learning and graph callers achieve higher SNV precision in repetitive genomic contexts (`NoGI` and `All`). However, `VarDictRust` achieves higher somatic indel sensitivity (`{{m:s6_HG008_FullWGS_v04_All_VarDictRust_v106_indel_r_pct}}` on `All`, `{{m:s6_HG008_FullWGS_v04_NoGI_VarDictRust_v106_indel_r_pct}}` on `NoGI`) than `ClairS` (`{{m:s6_HG008_FullWGS_v04_All_ClairS_v041_indel_r_pct}}`), `DeepSomatic` (`{{m:s6_HG008_FullWGS_v04_All_DeepSomatic_v160_indel_r_pct}}`), `Lancet2` (`{{m:s6_HG008_FullWGS_v04_All_Lancet2_NYGC_indel_r_pct}}`), and `Ultima DeepVariant Somatic` (`{{m:s6_HG008_FullWGS_v04_All_Ultima_DeepVariant_Somatic_indel_r_pct}}`), while at `{{m:s6_tit_vaf_1_pct}}` VAF (`1%` tumor purity) in our *in silico* titration (`s6_low_vaf_titration_truth_curve`), `VarDictRust` retains `{{m:s6_tit_p1_VarDictRust_snv_r_pct}}` SNV sensitivity (`{{m:s6_titration_0p5vaf_recall_ratio_vs_m2}}`× higher than `Mutect2` and `Strelka2`). Moreover, `VarDictRust` runs purely on commodity CPUs in a single `{{m:s5_h4_musl_mb}}` MB binary without GPU or FPGA dependencies.

## Conclusions

`VarDictRust` (`v{{m:version}}`) consolidates the three-language `VarDictJava -> R -> Perl` variant-calling pipeline into a single, memory-safe, statically compiled Rust binary that preserves exact numerical and allele equivalence (`ε = {{m:eps_tol}}`) with `{{m:oracle_version}}` across all `{{m:s2_modes_total}}` operational modes, `{{m:s5_cross_platform_arms}}` short-read sequencing chemistries, and `{{m:s6_ga4gh_cells}}` GA4GH `v3.5` genomic strata. By bounding memory to `O(tile + halo)` and accelerating execution by up to `{{m:s2_rchr1_speedup_vs_java}}`× on contiguous chromosomes (`{{m:s2_rchr1_rss_ratio_vs_java}}`× lower RSS) and `{{m:s4_exome_th32_speedup_vs_java}}`× on `32`-core whole exomes (`{{m:s4_exome_th32_rss_ratio_vs_java}}`× lower RSS), `VarDictRust` eliminates whole-genome out-of-memory failures and unlocks full-contig variant discovery across next-generation `T2T-Q100` and clinical `CMRG` benchmarks.

## Methods

### Consolidated Rust Architecture and Coordinate Type Safety
`VarDictRust` is implemented as a two-crate Rust workspace: `vardictrust-core` (the library engine, compiled with `#![forbid(unsafe_code)]` and zero `unwrap()`/`expect()`/`panic!()` calls outside unit tests) and `vardictrust` (the `clap` command-line interface, compatible with all `VarDictJava` v1.8.3 CLI flags). To prevent off-by-one coordinate defects between `0`-based half-open BAM/CRAM coordinates (`noodles`) and `1`-based inclusive VCF/VarDict internal coordinates, the type system enforces distinct `Pos0` and `Pos1` newtypes with explicit `.to_one_based()` and `.to_zero_based()` conversions. Sequence reads and reference slices are processed as raw byte slices (`&[u8]`) with Phred+33 saturation arithmetic (`Phred(byte.saturating_sub(33))`).

### Bounded Tile-Plus-Halo Streaming and Deterministic Realignment
When given a BED interval or `-R` region exceeding the configurable tile threshold (`default {{m:s1_tile_1m}}` bp), `VarDictRust` partitions the interval into non-overlapping ownership tiles $[T_k^{\text{start} }, T_k^{\text{end} })$ padded on both sides by a `{{m:rust_halo_kbp}}` kbp realignment halo (`Figure 1b`). Each tile is dispatched to a `Rayon` work-stealing thread pool, which streams alignments overlapping $[T_k^{\text{start} } - H, T_k^{\text{end} } + H)$ via `noodles` (supporting multi-threaded BGZF BAM and reference-decoded CRAM `-G`), performs read-level CIGAR modification (`cigar/modify.rs`), pileup accumulation (`cigar/parse.rs`), local indel/soft-clip realignment (`realign.rs`), structural variant assembly (`sv.rs`), and variant finalization (`tovars.rs`), and emits only variants whose canonical `Pos1` start coordinate falls within $[T_k^{\text{start} }, T_k^{\text{end} })$. All per-tile pileup maps are dropped immediately upon tile completion (RAII), bounding peak heap memory to active tiles in flight. Where `VarDictJava`'s output depends on `java.util.HashMap` bucket iteration order (`#282`), `VarDictRust` emulates exact JDK8 `HashMap` hash-spread, bin, resize, and treeify semantics via a verified `JavaHashMap` container, while using `IndexMap` (`LinkedHashMap`) and `BTreeMap` (`TreeMap`) everywhere else.

### In-Process Statistical Post-Processing and Banker's Rounding (`HALF_EVEN`)
To eliminate the external R (`teststrandbias.R` / `testsomatic.R`) and Perl (`var2vcf_valid.pl` / `var2vcf_paired.pl`) processes, `VarDictRust` implements hypergeometric Fisher exact two-sided p-value and conditional maximum-likelihood odds-ratio (`uniroot` zero-in with tolerance $\text{ulp}(1)^{0.25}$) computation directly in Rust (`stats/fisher.rs`), followed by native VCF 4.3 formatting (`output/`). Every floating-point metric (`AF`, `AdjAF`, `HIAF`, `SBF`, `ODDRATIO`, `SSF`, `MSI`, `QUAL`) passes through IEEE 754 round-half-to-even (`round_half_even` to 5 decimal places) matching R's `round(x, 5)` and Java's `DecimalFormat` (`HALF_EVEN`), reproducing both the no-`--fisher` trailing-zero format and the `--fisher` stripped-zero format within `ε = {{m:eps_tol}}` (`10^{-6}`).

### Cloud Benchmarking Infrastructure, Reproducibility Protocol, and Statistical Analysis
All `{{m:compute_cells}}` empirical compute cells (`{{m:total_cells}}` cells total including `evidence_certified`) were executed on a dedicated Google Cloud Platform (`GCP`) `{{m:host}}` instance (`{{m:nvme_raid0_tb}}` TB local NVMe RAID0 scratch; initial exploratory staging also validated compatibility on `c3d-standard-32` AMD EPYC Genoa nodes, with all reported paper timings standardized on `n2-standard-32` Ice Lake under commit `2a8e9a3` / `v{{m:version}}`, engine fingerprint `{{m:fingerprint}}`, performance fingerprint `{{m:perf_fingerprint}}`, total cloud spend `${{m:gcp_spend_usd}}` of `${{m:gcp_budget_usd}}` budget [`{{m:gcp_spend_pct}}`], `$ {{m:gcp_remaining_usd}}` remaining, and `{{m:gcs_cache_gib}}` GiB persistent GCS archive at `${{m:gcs_weekly_usd}}`/week). Each timing cell was run with `n = 3` independent technical replicates wrapped in `/usr/bin/time -v` to record wall-clock elapsed seconds and peak `Maximum resident set size (kbytes)`. Binary concordance proportions are reported with exact Clopper-Pearson `95%` binomial confidence intervals ($\alpha = 0.05$). Non-parametric runtime and memory comparisons across the `12` Tier-P cells were evaluated using two-sided Mann-Whitney $U$ tests and exact paired sign-flip permutation tests ($2^{-12}$). Variant truth evaluation was performed using `rtg vcfeval` (`v3.12.1`) with official NIST GIAB high-confidence BED masks (`HG002 v4.2.1`, `HG002 v5.0Q T2T-Q100`, `CMRG v1.00`, `Mosaic v1.10`, `HG005 v4.2.1`, `SEQC2 v1.2.1`, and `HG008 v0.3`/`v0.4` including the `7` official NIST `Liss_lab` modern/commercial caller VCFs). Controlled *in silico* tumor-purity titrations (`20%`, `10%`, `5%`, `2%`, `1%`) were generated by deterministic seed-controlled `samtools view -s` subsampling and merging of HG008 tumor and matched normal BAMs (`Supplementary Methods`).
