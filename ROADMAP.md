# VarDictRust Roadmap

VarDictRust v1.0.0 replicates VarDictJava v1.8.3 output byte-for-byte on valid inputs, including the upstream behaviors documented in `DIVERGENCES.md` and [`docs/upstream-bugs.md`](docs/upstream-bugs.md).

To keep end-user CLI ergonomics simple while guaranteeing that rigorously tested VarDictJava v1.8.3 parity can always be reproduced, post-1.0 evolution follows a **`bwa-mem3`-Style `--compat=<vardictjava|off>` Compatibility & SemVer Model** (`Choice 1A`, tracked in `VarDictRust#94`):
- **`v1.0.x` (Parity Baseline):** Parity-only execution; all invocations are **100% byte-identical to VarDictJava v1.8.3**, and explicit **`--parity`** (`--compat vardictjava-1.8.3`) landed in `v1.0.8` (`PR #102`, `VarDictRust#94` Phase 1a) so production pipelines could forward-compatibly pin v1.8.3 parity.
- **`v1.1.x` (`v1.1.0+`):** Default invocations remain **100% byte-identical to `VarDictJava v1.8.3` + `var2vcf_*.pl`** (`--compat=vardictjava` by default, accepting aliases `vardictjava-1.8.3` and `1.8.3` plus the `--parity` shorthand). Introduces opt-in **`--compat=off`** (`COMPAT_OFF`, stamping `##VarDictRustCompat=off` in VCF headers) to activate bonafide correctness fixes via the `#[non_exhaustive]` `CompatProfile` struct (`crates/vardictrust-core/src/config.rs`) without CLI flag explosion (zero per-bug `--fix <id>` CLI flags), alongside **18/18 `var2vcf_*.pl` flag parity** via `--vcf-all-alleles` / `--all-alleles` (`90` total CLI flags across `7` functional groups).
- **`v2.0.0+`:** Evaluates promoting **`--compat=off`** to the default out-of-the-box behavior after community concordance review, while **`--compat=vardictjava`** (and **`--parity`**) permanently reproduces exact `VarDictJava v1.8.3` byte-for-byte behavior with a single flag.

Under the hood, each individual correction is represented as an explicit field on `CompatProfile` (`#[non_exhaustive]`) and lands in `COMPAT_OFF` (`--compat=off`) only with:
1. A reproducible testcase demonstrating `VarDictJava v1.8.3` behavior.
2. A dedicated unit test in `crates/vardictrust-core` exercising both `COMPAT_VARDICTJAVA_1_8_3` and `COMPAT_OFF`.
3. A [Tier-1](docs/testing/test-matrix-and-ci-audit.md#tier-1) intermediate table and [Tier-2](docs/testing/test-matrix-and-ci-audit.md#tier-2) differential test run proving `--compat=vardictjava` (and default CLI output across all `v1.x` releases) remains byte-identical to v1.0.0 across all regression suites.
4. A diff-confinement proof verifying that each `CompatProfile` switch under `--compat=off` alters only targeted records, produces zero off-target diffs, and maintains [Tier-3](docs/testing/test-matrix-and-ci-audit.md#tier-3) truth concordance (see [Master Test Matrix](docs/testing/test-matrix-and-ci-audit.md)).

## v1.1.x `CompatProfile` (`--compat=off`) & `--vcf-all-alleles` Catalog

`v1.1.0` ships **13 `CompatProfile` switches** (`1..7` Wave 1 + `8..13` Wave 2) under `--compat=off` (`COMPAT_OFF`, stamping `##VarDictRustCompat=off` in VCF headers) plus **18/18 `var2vcf_*.pl` post-filter flag parity** via `--vcf-all-alleles` (alias: `--all-alleles`, completing the `90`-flag CLI surface across `7` functional groups while keeping `-A <INT>` as `VarDictJava`'s `sv_min_af` `[default: 4]`):
1. `#116` (`sanitize_sample_info`): Bijective VCF 4.2 percent-encoding on `INFO/SAMPLE=...` (`%`, `;`, `=`, `,`, whitespace/control, `""` -> `-`, `-` -> `%2D`, `.` -> `%2E`).
2. `#342` (`standard_dup_symbolic_alt`): Standard `<DUP>` symbolic `ALT` and non-negative `i64` span when `mlen < 100` (including `-L <= 100`), plus unified homozygous `genotype1` `<DUP>` span (`2 * SVFLANK + dup_val`, `ToVarsBuilder.java:619` vs `:700`).
3. `#292` (`shift3_3prime_alleles`): FASTA-valid 3'-shifted (`-3`) deletion/insertion `REF`/`ALT` alleles with CRISPR double-shift guard.
4. `#369` (`strict_region_bounds`): Merged-interval target bounds enforcement (`start_pos >= 1` within requested intervals).
5. `UB-1`/`UB-2` (`suppress_pileup_sentinels`): Suppress `-p` pileup `<R,R>`/`N/N` zero-depth sentinel rows in Simple and Amplicon modes.
6. `live_duprate`: Live `u64` `DUPRATE` from `RecordPreprocessor` duplicate/total read counts across untiled and split-tile runs.
7. `preserve_mixed_sex_contigs`: Mixed sex/mitochondrial contig preservation (`X`+`chrX`, `Y`+`chrY`, `MT`+`chrM`) + strict total order on `chrom_compare`.
8. `402` (`cigar_homopolymer_merge`): Absorb negative trailing `M` (`rm < 0`) into `rdoff_corr` during homopolymer multi-indel merges in `CigarModifier`, returning `Err(JavaThrows)` immediately if `rdoff_corr <= 0` ([VarDictJava PR #402](https://github.com/AstraZeneca-NGS/VarDictJava/pull/402)).
9. `eqx-read-length` (`eqx_cigar_read_length`): Treat `=` (`SequenceMatch`) and `X` (`SequenceMismatch`) CIGAR operators equivalently to `M` (`Match`) across read-length, CIGAR coalescing, realignment, dedup, and prescan paths (`CigarParser.java:1605-1629, 1990-1991`).
10. `ub5` (`preserve_discordant_svs`): Preserve single-sample symbolic SVs (`<DUP>`, `<INV>`, `<DEL>`) with `spanpairs > 0` when `splitreads == 0` unless `--min-splitreads` was explicitly overridden ([UB-5](docs/upstream-bugs.md#ub-5)).
11. `ub6` (`mark_dup_sv_inclusive_end`): Pass pre-decrement cluster end `mark_pe` (`pe + 1` vs post-decrement `pe`) to `mark_dup_sv` in `svfdup` when `tbp != 0 && tbp < pe` ([UB-6](docs/upstream-bugs.md#ub-6)).
12. `sv-lazy-mate-pileup` (`sv_lazy_mate_pileup`): Gate `find_inv_sub_paths` mate-window loads on local `>= 12 bp` soft-clip presence and defer `partial_pipeline_paths` until `find_match_rev` + gap validation succeed (`StructuralVariantsProcessor.java:519-675`).
13. `rounding-underflow-tie` (`exact_binary_half_even`): Bypass OpenJDK `DecimalFormat` `DigitList` fixed-point underflow truncation (`±5e-{4,5,6,9}`) so exact binary IEEE-754 `f64` values round up to `±10^-d` (`Utils.java:101-103`).

Owner-ruled 2026-10-22 (codified in `AGENTS.md §5`): Rust-only artifacts whose prior behavior never matched the `VarDictJava v1.8.3` oracle on valid inputs ship **UNGATED as default behavior** once verified to `MATCH` the live oracle across all regression suites (any unreleased gating plumbing is removed rather than kept as a no-op, whereas true output-changing corrections to upstream v1.8.3 bugs live on `CompatProfile` under `--compat=off`).

## Post-1.0 Features

Post-1.0 features ship strictly as opt-in modes so default invocations (`--compat=vardictjava` / `--parity`) remain byte-identical to the v1.0.0 baseline and maintain bounded peak memory ($\le 3\text{ GB}$):

- **Unique Molecular Identifiers (UMI) (Planned, v2.0):** Integrated duplex and single-index consensus calling (`--umi-tag RX --duplex`) within coordinate-sorted 100 kb streaming tiles (modeled on Fulcrum Genomics `fgumi`).
- **Read-Pair Orientation Bias Modeling (`F1R2`/`F2R1`) (Planned, v2.0):** Empirical Beta-Binomial orientation bias filtering (`--orientation-bias-model`) to suppress single-strand FFPE cytosine deamination (`C>T`/`G>A`) and acoustic-shearing 8-oxoG (`C>A`/`G>T`) artifacts at `<2%` VAF.
- **Long-Read NGS Support (`--preset hifi|ont`) (Planned, v2.0):** Calibrated homopolymer/indel error profiles, >125 bp SV clip thresholds, supplementary alignment (`SA:Z`) split-read chaining, `MM`/`ML` and `HP`/`PS` tag preservation, and step-bounded 2-piece affine Wavefront Alignment (`WFA2` / `block-aligner`, modeled on PacBio `sawfish`, `trgt`, and `aardvark`).
- **Native Compressed VCF, Consolidated `var2vcf` Post-Filters, `--compat` Profiles & Run Telemetry:** **SHIPPED (`v1.0.8`–`v1.1.0`):** `--output <PATH>` (plain `.vcf`/`.var` and multithreaded BGZF `.gz`/`.bgz` via `noodles::bgzf::io::MultithreadedWriter`), direct `.tbi` Tabix (`--tbi` / `--index` via `noodles::tabix`) and `.csi` (`--csi` via `noodles::csi`) index generation, all **18/18** consolidated `var2vcf_valid.pl` / `var2vcf_paired.pl` CLI flags including `--vcf-all-alleles` / `--all-alleles` (resolving the legacy `-A` flag collision with `var2vcf_valid.pl`) plus `--completions` / `--manpage` and `--compat=<vardictjava|off>` (`##VarDictRustCompat=off`) completing the `90`-flag CLI surface across `7` functional groups (`--no-end`, `--pass-only`, `--paired-strict`, `--vcf-all-alleles` / `--all-alleles`, `--vcf-pval`, `--min-splitreads`, `--no-pstd-filter`, `--vcf-af`, `--vcf-min-depth`, `--vcf-min-vd`, `--vcf-qmean`, `--vcf-mapq`, `--vcf-pmean`, `--vcf-sn`, `--vcf-max-nm`, `--vcf-gt-freq`, `--vcf-msi`, `--vcf-cluster-dist` with `SingleRecordStreamer` bounded-memory cluster buffering; documented in [`docs/migration.md`](docs/migration.md)), and `--stats-json <PATH>` pipeline telemetry; `--preset wgs|wes|amplicon|ctdna` is slated for `v1.2.0`.
