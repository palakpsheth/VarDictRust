# VarDictRust Roadmap

VarDictRust v1.0.0 replicates VarDictJava v1.8.3 output byte-for-byte on valid inputs, including the upstream behaviors documented in `DIVERGENCES.md` and [`docs/upstream-bugs.md`](docs/upstream-bugs.md).

To keep end-user CLI ergonomics simple while guaranteeing that rigorously tested VarDictJava v1.8.3 parity can always be reproduced, post-1.0 evolution follows a **`bwa-mem3`-Style `--compat=<vardictjava|off>` Compatibility & SemVer Model** (`Choice 1A`, tracked in `VarDictRust#94`):
- **`v1.0.x` (Parity Baseline):** Parity-only execution; all invocations are **100% byte-identical to VarDictJava v1.8.3**, and explicit **`--parity`** (`--compat vardictjava-1.8.3`) landed in `v1.0.8` (`PR #102`, `VarDictRust#94` Phase 1a) so production pipelines could forward-compatibly pin v1.8.3 parity.
- **`v1.1.x` (`v1.1.0+`):** Default invocations remain **100% byte-identical to `VarDictJava v1.8.3` + `var2vcf_*.pl`** (`--compat=vardictjava` by default, accepting aliases `vardictjava-1.8.3` and `1.8.3` plus the `--parity` shorthand). Introduces opt-in **`--compat=off`** (`COMPAT_OFF`, stamping `##VarDictRustCompat=off` in VCF headers) to activate bonafide correctness fixes via the `#[non_exhaustive]` `CompatProfile` struct (`crates/vardictrust-core/src/config.rs`) without CLI flag explosion (zero per-bug `--fix <id>` CLI flags), alongside **18/18 `var2vcf_*.pl` flag parity** via `--vcf-all-alleles` / `--all-alleles`, clinical workflow presets via `--preset <wgs|wes|amplicon|ctdna>` (`##VarDictRustPreset=<PRESET>`), single-primer extension amplicon support via `--amplicon-single-primer` / `-sp`, and hidden `vardictcpp v2..v4` drop-in CLI aliases (`--vcfall`, `--noend`, `--vcfpass`, `--vcf`) (`92` total CLI flags across `7` functional groups).
- **`v2.0.0+`:** Evaluates promoting **`--compat=off`** to the default out-of-the-box behavior after community concordance review, while **`--compat=vardictjava`** (and **`--parity`**) permanently reproduces exact `VarDictJava v1.8.3` byte-for-byte behavior with a single flag.

Under the hood, each individual correction is represented as an explicit field on `CompatProfile` (`#[non_exhaustive]`) and lands in `COMPAT_OFF` (`--compat=off`) only with:
1. A reproducible testcase demonstrating `VarDictJava v1.8.3` behavior.
2. A dedicated unit test in `crates/vardictrust-core` exercising both `COMPAT_VARDICTJAVA_1_8_3` and `COMPAT_OFF`.
3. A [Tier-1](docs/testing/test-matrix-and-ci-audit.md#tier-1) intermediate table and [Tier-2](docs/testing/test-matrix-and-ci-audit.md#tier-2) differential test run proving `--compat=vardictjava` (and default CLI output across all `v1.x` releases) remains byte-identical to v1.0.0 across all regression suites.
4. A diff-confinement proof verifying that each `CompatProfile` switch under `--compat=off` alters only targeted records, produces zero off-target diffs, and maintains [Tier-3](docs/testing/test-matrix-and-ci-audit.md#tier-3) truth concordance (see [Master Test Matrix](docs/testing/test-matrix-and-ci-audit.md)).

## Post-1.0 Features

Post-1.0 features ship strictly as opt-in modes so default invocations (`--compat=vardictjava` / `--parity`) remain byte-identical to the v1.0.0 baseline and maintain bounded peak memory ($\le 3\text{ GB}$):

- **Unique Molecular Identifiers (UMI) (Planned, v2.0, [`AstraZeneca-NGS/VarDictJava#374`](https://github.com/AstraZeneca-NGS/VarDictJava/issues/374)):** Integrated duplex and single-index consensus calling (`--umi-tag RX --duplex`) within coordinate-sorted 100 kb streaming tiles (modeled on Fulcrum Genomics `fgumi` and [`fengqing-dong/VarDictJava`](https://github.com/fengqing-dong/VarDictJava)).
- **Read-Pair Orientation Bias Modeling (`F1R2`/`F2R1`) (Planned, v2.0):** Empirical Beta-Binomial orientation bias filtering (`--orientation-bias-model`) to suppress single-strand FFPE cytosine deamination (`C>T`/`G>A`) and acoustic-shearing 8-oxoG (`C>A`/`G>T`) artifacts at `<2%` VAF.
- **Long-Read NGS Support (`--preset hifi|ont`) (Planned, v2.0, [`AstraZeneca-NGS/VarDictJava#368`](https://github.com/AstraZeneca-NGS/VarDictJava/issues/368)):** Calibrated homopolymer/indel error profiles, >125 bp SV clip thresholds, supplementary alignment (`SA:Z`) split-read chaining, `MM`/`ML` and `HP`/`PS` tag preservation, and step-bounded 2-piece affine Wavefront Alignment (`WFA2` / `block-aligner`, modeled on PacBio `sawfish`, `trgt`, and `aardvark`).
- **Native Compressed VCF, Consolidated `var2vcf` Post-Filters, `--compat` Profiles, Clinical Presets & Run Telemetry:** **SHIPPED (`v1.0.8`–`v1.1.0`, [`AstraZeneca-NGS/VarDictJava#324`](https://github.com/AstraZeneca-NGS/VarDictJava/issues/324), [`clintval/vartovcf#161`](https://github.com/clintval/vartovcf/pull/161), [`palakpsheth/VarDictRust#94`](https://github.com/palakpsheth/VarDictRust/issues/94)):** `--output <PATH>` (plain `.vcf`/`.var` and multithreaded BGZF `.gz`/`.bgz` via `noodles::bgzf::io::MultithreadedWriter`), direct `.tbi` Tabix (`--tbi` / `--index` via `noodles::tabix`) and `.csi` (`--csi` via `noodles::csi` `Indexer::<LinearIndex>` spanning-SV `loffset` propagation) index generation, all **18/18** consolidated `var2vcf_valid.pl` / `var2vcf_paired.pl` CLI flags including `--vcf-all-alleles` / `--all-alleles` (resolving the legacy `-A` flag collision with `var2vcf_valid.pl`) plus `--amplicon-single-primer` / `-sp`, hidden `vardictcpp v2..v4` drop-in aliases (`--vcfall`, `--noend`, `--vcfpass`, `--vcf`), `--completions` / `--manpage`, `--compat=<vardictjava|off>` (`##VarDictRustCompat=off`), and `--preset wgs|wes|amplicon|ctdna` (`##VarDictRustPreset=<PRESET>`) completing the `92`-flag CLI surface across `7` functional groups (`--no-end`, `--pass-only`, `--paired-strict`, `--vcf-all-alleles` / `--all-alleles`, `--vcf-pval`, `--min-splitreads`, `--no-pstd-filter`, `--vcf-af`, `--vcf-min-depth`, `--vcf-min-vd`, `--vcf-qmean`, `--vcf-mapq`, `--vcf-pmean`, `--vcf-sn`, `--vcf-max-nm`, `--vcf-gt-freq`, `--vcf-msi`, `--vcf-cluster-dist` with `SingleRecordStreamer` bounded-memory cluster buffering; documented in [`docs/migration.md`](docs/migration.md)), and `--stats-json <PATH>` pipeline telemetry.
